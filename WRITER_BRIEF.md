# Technical writer brief — HuVLLM

You are writing documentation for **HuVLLM**, a replication study evaluating
training-free video-LLM token-reduction methods on MotionBench across two
backbones. This file tells you what the project is, what is already written,
what is true, how to get more data, and what you must not do.

You do **not** have cluster access. All results you need are cached locally.
New runs are dispatched by a separate agent that owns the Carya connection —
if you need a number that does not exist yet, say so explicitly rather than
estimating it.

---

## 1. What the project measures

MotionBench: 8,052 multiple-choice video questions, **4,018 scoreable** after
removing 4,034 `NA` items. Methods are evaluated at a standardized **32 frames**
and **15% visual-token retention** where the method exposes such a knob.
Decoding is greedy (`do_sample=False`), answers letter-matched A–D.

Two backbones:

| Backbone | Baseline accuracy |
|---|---:|
| LLaVA-OV-7B (Qwen 1.5) | 52.66% (2116/4018) |
| Qwen3-VL-8B | 62.52% (2512/4018) |

Statistical floor: differences below **±1.54 pt** are not resolvable at n=4018.
Significance is McNemar on paired predictions, **χ² ≥ 3.84** for p<0.05. Do not
describe a sub-1.54-pt difference as an improvement, and do not rank methods
that are statistically tied.

## 3. The single most important concept: the verification gate

The dominant failure mode in this project is **silent success** — a run that
completes, reports a plausible accuracy, and did nothing at all. Four distinct
classes have been caught: a stub method that never ran, discarded hooks, a
non-contiguous visual span that made a patch a no-op, and a disk-full job that
SLURM reported as COMPLETED.

A result counts only when **both** signals are present:

1. **ACTIVE log** — the mechanism printed evidence it executed.
2. **Prediction divergence** — the output actually differs from the bare backbone.

An ACTIVE log alone is worthless. Because greedy decoding is exactly
deterministic, two identical runs diverge by **0 / 8,052** — verified on three
independent pairs. That is what makes "0 divergence ⇒ no-op" a valid proof.

Never describe a method as evaluated, working, or comparable unless it passed
both. Where a result is ungated, say so in the same sentence as the number.

## 4. Facts that are easy to get wrong

- **`fastv_run1` is the bare LLaVA-OV backbone**, not a FastV run. It is the old
  stub run where `apply_fastv()` did nothing. It is the baseline reference.
- **VisionZip runs on LLaVA-1.5-7B**, not LLaVA-OV — it patches `CLIPVisionTower`,
  which LLaVA-OV does not have. Its 40.09% is **not** comparable to the LLaVA-OV
  rows. Never place it in a LLaVA-OV comparison table.
- **`llava-ov-7b` and `llava-ov-7b-qwen2` are byte-identical** weight directories.
  Proven by a 0-divergence pair across them. Runs citing either are comparable.
- **FastV's `--fastv_r` is the DROP fraction.** Retention 0.10 means `--fastv_r 0.9`.
- **Sampled runs are never comparable to gated runs** and must never be merged
  into `master-results.md`. Two sampled runs differ by chance, so the divergence
  gate cannot apply to them. They exist only to show answer distribution.
- **DyTo is reported as "DyTo (reconstructed TW-FINCH)"**, never as plain "DyTo".
  Its published artifacts are not reproducible; we reconstructed the clustering.
- **Repetition Count is at chance for every method**, including the backbones
  (23.8% on LLaVA-OV). Do not present movement in that column as a finding.
- **FastV's paper default is R=50%.** Our standardized 15% and the sweep down to
  10% are well outside its validated range. Say so whenever citing its drop.

## 5. How to gather more

Everything below runs locally with no cluster access.

```bash
# Cached per-run outputs: summary.json + results.jsonl, one dir per run
ls results-cache/

# Regenerate the combined report and the retention tables from the cache
python3 scripts/build_findings.py
python3 scripts/build_retention_tables.py --local > docs/RETENTION_TABLES.md
python3 sampled-llava-ov/build_distribution.py --local
```

`results.jsonl` has one row per sample:
`{idx, video_path, question_type, ground_truth, prediction, correct}`,
where `correct` is `null` for the 4,034 NA items. `summary.json` carries the
accuracy, the counts, the model path, and the method's parameters.

That schema is enough to compute, without any new runs: accuracy, per-category
accuracy, answer distribution, pairwise divergence between any two runs, McNemar
tables, and which specific samples changed. Prefer computing a number from the
cache over quoting one from prose — prose can drift, `results.jsonl` cannot.

To verify a run's gate status: `python3 scripts/check_run.py <run_dir>
--expect-method <m> --vs-baseline <ref>`.

**If a run directory you need is absent from `results-cache/`, it has not been
fetched or has not finished.** Do not infer its value. Ask for it.

## 6. Constraints

- **Never edit anything under `stage1-llava-ov/`, `stage3-qwen3-vl/`, or
  `other-backbones/`.** Those are the gated evaluation scripts that produce the
  reported numbers. Study variants live in their own folders
  (`sampled-llava-ov/`, `analysis/fastv-selection-study/`) precisely so the
  originals stay untouched.
- **Never run inference locally or on a login node.** All jobs go through SLURM,
  dispatched by the agent that owns cluster access.
- Do not soften a negative result. Methods that lost accuracy, ports that turned
  out to be no-ops, and analyses that remain open are the substance of this
  project, not blemishes on it.
- Where a conclusion is not yet settled, mark it open and state what experiment
  would settle it. `docs/FASTV_COLLAPSE_ANALYSIS.md` §7 is the model for this.

## 7. House style

- No emojis in prose. The status glyphs already used in `RESULTS.md` tables
  (`✅`, `⚠️`) are existing table vocabulary — keep them consistent there, do not
  introduce new ones.
- Tables for anything with more than two comparable quantities. Right-align
  numeric columns.
- State the mechanism, then the evidence, then the caveat. Not the reverse.
- Every accuracy gets its denominator or its n on first use in a document.
- Link code as `[file.py:42](path/file.py#L42)`. Relative paths from repo root.
- Be concise. Cut background the reader can get from the linked page.
- Prefer "the run diverged on 23 of 8,052 predictions" over "the results were
  broadly similar". Numbers, not adjectives.

### Publication risk on two specific numbers

FastV (36.78%) and PruneVID-OV (38.20%) on LLaVA-OV fail with signatures that
match each other to within about one point on every measure — accuracy, D-rate,
broke:fixed ratio, and flatness across retention — despite being different
algorithms operating at different layers with different selection rules. Both
drive pruning through the same `PrunableDynamicCache.kv_cache` route.

The queued `keepall` arm keeps every visual token while still traversing that
route, so it must reproduce the 52.66% backbone if the harness is sound.

**If `keepall` does not return ~52.66%, those two rows in
[docs/RESULTS.md](docs/RESULTS.md) and
[memory-bank/claude/master-results.md](memory-bank/claude/master-results.md)
are harness artifacts and have to be retracted and re-run.** Do not publish
anything whose argument rests on either number until that control reports.
